# Build Control Flow

Purpose
-------
This document describes the build control flow for creating runtime artifacts used by the stack: building images, running the integration prober, and the repository CI smoke tests that validate the Caddyfile render and Caddy "adapt" behaviour.

High-level inputs / outputs
--------------------------
- Inputs
  - Source files under `/opt/openproject` (Dockerfiles, `proxy/Caddyfile.template`, scripts)
  - Build-time args or environment variables used when building images
- Outputs
  - Docker images (local): `openproject/proxy-integration-test:latest`, `openproject/proxy-hello-integration:latest` (legacy), other service images
  - Temporary integration compose project in `/tmp/network_probe`

Key scripts & files
--------------------
- `proxy/test/run_integration_test.sh` — builds and runs the integration prober image(s)
- `proxy/test/prober.sh` — interactive driver for the prober
- `scripts/ci/smoke_render_caddy.sh` — CI smoke script to render and validate the Caddyfile
- `.github/workflows/smoke-render-caddy.yml` — workflow that runs the smoke script on PRs

Build control flow (rendered tree)
----------------------------------
This ASCII tree shows the typical build flow for integration/test artifacts.

BUILD_FLOW

```text
root
├─ (1) pre-build checks
│  ├─ ensure docker is available and daemon running
│  ├─ ensure build context files exist (`Dockerfile`, `Caddyfile`, `app.py`)
│  └─ ensure no port conflicts on the host (or pick a free port)
├─ (2) create temp project
│  ├─ make temp dir under `/tmp/network_probe`
│  ├─ write `Dockerfile`, `Caddyfile`, `entrypoint.sh`, `app.py` into temp dir
│  └─ write `docker-compose.yml` for the integration build/run
├─ (3) build images
│  ├─ `docker compose build --pull --no-cache` (or equivalent)
│  └─ tag images as `openproject/...:latest` in temp project
├─ (4) run integration compose
│  ├─ `docker compose up -d` inside temp dir
│  └─ wait for containers to start and services to be healthy
├─ (5) run smoke tests
│  ├─ curl the proxy endpoint and assert expected body/status
│  └─ on failure, collect logs (`docker logs`) and output diagnostics
└─ (6) tear down or persist
  ├─ If `down` requested: `docker compose down` for temp project
  └─ If `clean` requested: `docker compose down -v --rmi local` and remove temp dir
```

CI smoke flow
------------
- The CI job (`.github/workflows/smoke-render-caddy.yml`) runs `scripts/ci/smoke_render_caddy.sh` which:
  1. Installs `gomplate` and `caddy` binaries (or runs container-based `caddy adapt`)
  2. Renders `proxy/Caddyfile.template` with test env values
  3. Runs `caddy adapt` for validation
  4. Fails the job on rendering/validation errors

Error modes & notes
-------------------
- Build failures: missing base images, network issues when pulling layers, or Docker permissions
- Runtime failures in prober: Caddy misconfiguration (Caddyfile syntax), unreachable backend (DNS inside container), port conflicts
- CI pitfalls: CI runners may lack docker-in-docker; prefer containerized `caddy adapt` in CI to validate formatting and syntax

Best practices for builds
-------------------------
- Keep the integration prober's image small (base on `caddy:2`, add a tiny Python runtime only if needed)
- Prefer ephemeral test images for CI; avoid pushing test tags to registries
- Use the prober's `--pick-port` option to avoid collisions on shared hosts
- Add preflight checks to the prober scripts to surface issues early

Quick commands
--------------
- Build locally (temp project):
  /opt/openproject/proxy/test/run_integration_test.sh --pick-port up
- Tear down:
  /opt/openproject/proxy/test/run_integration_test.sh down
- Clean temp images and project files:
  /opt/openproject/proxy/test/run_integration_test.sh clean

Dependencies
------------
Build and test flows require the following tools to be available on the host where you run them:

- docker (>= 20.10.0) and Docker Compose (>= 2.0.0)
- build-time utilities (curl, tar) for helper scripts
- gomplate (for template rendering in some CI flows)

Quick install hints (Debian-based systems)

```bash
sudo apt update
sudo apt install -y docker.io docker-compose-plugin curl tar

# Install gomplate if needed
sudo curl -sL https://github.com/hairyhenderson/gomplate/releases/latest/download/gomplate_linux_amd64 -o /usr/local/bin/gomplate
sudo chmod +x /usr/local/bin/gomplate

# If you need to run caddy adapt locally for CI testing, install caddy (see CONFIGURATION_FLOW.md)
```

Notes
-----
- CI runners may not support Docker-in-Docker; prefer containerized validation steps (run `caddy adapt` in the `caddy:2` container) or use dedicated runners with Docker.
- For reproducible builds, pin Docker base images in Dockerfiles or use image digests.
